# UNOFFICIAL Tails container (adapted from a Tails 7.16 ISO root filesystem) for Kasm  - v0.4

**This is not Tails.** It is the Tails 7.16 root filesystem (extracted from an ISO the owner holds) run as an unprivileged Docker container under KasmVNC.
Not provided: the Tails kernel, memory wipe on shutdown, MAC anonymisation, Tails' own firewall/netns/onion-grater/AppArmor policy set, Wayland (X11 under KasmVNC instead). No claim of Tails support or security equivalence. A container shares the host kernel.

## What is enforced (each item was tested in a real Kasm session)
- **Tor-only egress, outside the desktop.** Desktops sit on an *internal* Docker network (`kbtails_int`, no route out). The only service they can start a connection to is the gateway container (`gateway/`: cap-drop ALL, read-only, no route table entries for the LAN). Direct internet, DNS, IPv6, LAN, `karen` and the Docker bridge fail with "Network is unreachable" (also at start-up, reconnect and when Tor is down). No Tor client runs in the desktop (no Tor-over-Tor).
- **Gateway front end `gateway/kbgw.py`.** Tor listens only on the gateway's loopback. Desktops reach (a) SOCKS5 front ends on the Tails ports and (b) a filtered control port:
  - *destination policy on the proxy path actually used*: non-global addresses, single-label/internal names, the owner's public host names (every name under the owner's domain) and the WAN/alias addresses (`gateway/deny.conf`) are refused before Tor is asked; clear-net names are resolved through Tor first and the connection is made to the verified address (no resolve/connect race); onion names pass through;
  - *per-desktop circuit isolation*: the SOCKS user name sent to Tor is prefixed with the desktop's IP and an epoch;
  - *filtered control port 9051*: null authentication towards the desktop, SAFECOOKIE towards Tor; GETINFO allow-list (version, bootstrap phase, circuit-established, own circuit/stream status, ns/id, ip-to-country, net/listeners/socks), CIRC/STREAM/STATUS_CLIENT (bootstrap events only) subscriptions limited to the desktop's own circuits and streams, `SIGNAL NEWNYM` = new epoch + closing only the desktop's own circuits (never the global signal), `CLOSECIRCUIT` only on own circuits, no SETCONF/SAVECONF/raw access.
- **Truthful status in the Tails UI.** `kb-torstatus` keeps `/run/tor-has-bootstrapped/done` (read by Tails' GNOME Tor-status extension and Tor Browser) present only while the gateway reports bootstrap 100 % and an established circuit. `kb-onioncircuits` runs Tails' circuit viewer against the filtered control port (own circuits only). `kb-tca` replaces the Tor Connection Assistant launcher (which needs systemd and a network namespace) by a dialog that shows the true gateway state; bridges are managed by the gateway.
- **Tails' own Tor Browser** (Flatpak `org.boum.tails.TorBrowser`, bubblewrap): per-container seccomp profile (Docker default plus `unshare/setns/mount/umount/umount2/pivot_root/clone/sethostname`, **minus `ptrace`/`process_vm_*`/`kcmp`**), AppArmor profile `kb-tails` (docker-default derivative adding `userns`, `mount`, `pivot_root`; denies `/data` and `/share`; no ptrace between processes), and the argument shim `kb-bwrap`. Browser session-private profile: the Tails template links `places.sqlite` to a Tails-only path (`/home/amnesia/...`); `kb-tor-browser` repoints that link to a store in the disposable home.
- **Runtime-verified sandbox** (`kb-sbx-test`): inside the sandbox the process has its own user and mount namespace, no capabilities, `NoNewPrivs`, two seccomp filters, AppArmor `kb-tails`, cannot `unshare` (user or mount) again, cannot `ptrace`, sees neither `/data` nor `/share`, has no network except through the gateway.
- **Peer isolation** (`host/kbtails-isolation`): Docker forwards same-bridge traffic at layer 2 (no br_netfilter), so iptables never saw desktop-to-desktop or desktop-to-`kasm_proxy` traffic. An nftables *bridge-family* table allows only replies, desktop -> gateway and `kasm_proxy` -> desktops; everything else inside `kbtails_int` is dropped.

## Remaining boundary (not equivalent to booted Tails; requirement stays OPEN)
- **No PID namespace in the browser sandbox.** Docker masks parts of `/proc`; the kernel then refuses a fresh procfs in a nested user namespace ("mount_too_revealing"). Unmasking needs `systempaths=unconfined`, a CLI-only option that Kasm's docker-py 7.1.0 cannot set (no `masked_paths`/`readonly_paths`). The shim binds the container's `/proc` instead and drops `--unshare-pid`; the sandboxed browser can still *see* (not ptrace) other processes of the same desktop container. Nested user namespaces are blocked by Flatpak's seccomp filter instead of `--disable-userns`.
- No Tails kernel, memory wipe, MAC anonymisation; X11 under KasmVNC.
- `NEWNYM` is per-desktop (gateway-side epoch), which is not identical to Tails' global signal.
- `/data` and `/share` are added by Kasm's group setting `volume_mapping` (All Users) to every workspace; this workspace denies them via AppArmor but cannot remove the mounts without changing the group setting for all workspaces.
- Screen lock: GNOME's lock needs GDM and a local login that do not exist here, so it is disabled (no misleading notice). The session is protected by Kasm's authentication, the per-session connection token and Kasm's idle disconnect.

## Install (local image: preload required, not downloadable)
1. On the Kasm agent host: build the image from your own Tails rootfs (`Dockerfile` here builds on the imported rootfs image `...:0.3`) and tag it `ghcr.io/daledibbadel/tails-unofficial:0.4`. Start the gateway with `gateway/gw_up.sh` (stage `torrc deny.conf kbgw.py` in `/tmp/kbgw-stage`; it creates the networks `kbtails_int`, `kbtails_eg` and the container `kbtails-tor-gw`). Load `profiles/kb-tails.apparmor` with `apparmor_parser -r`. Install `host/kbtails-isolation.sh` as `/usr/local/sbin/kbtails-isolation` and enable `host/kbtails-isolation.service`.
2. Add the registry workspace with Docker Registry left blank (local image); the image is protected from Kasm's pruner by the workspace reference and the running gateway container.
